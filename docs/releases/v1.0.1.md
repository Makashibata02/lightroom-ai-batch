# Lightroom AI Batch v1.0.1

## 中文

这是稳定性修复，不增加新的照片处理阶段。

- SDK 明确报错后及时结束等待；照片不可编辑时记录原因，安全退出后继续下一张。
- Denoise、预设和 AI 蒙版操作共用串行门闩；必须确认调用返回，不仅依赖界面状态。
- 超时/取消后等待旧调用安全退出。仍未返回时停止后续提交并明确提示重启，不再让新任务悄悄排队。
- worker 增加异常退出清理与 operation 身份校验，防止残留运行标志阻挡后续任务。
- 菜单查询/取消优先定位实际运行任务；重复点击启动只显示当前任务。MCP 启动返回实际 QUEUED/RUNNING 状态。
- 状态增加当前照片、队列位置、心跳、SDK 调用返回状态及恢复要求，中英界面同步更新。
- 保持内部插件 ID、配置与处理记录兼容；幂等 `pipelineVersion` 保留 1.0.0，升级不会自动重跑全部照片。
- 中断后默认重跑补完空蒙版清理，不重复应用已完成预设；强制重跑先清除 processed 完成标记，最终通过后再恢复。

本地验收：五张测试 RAW 全部完成（508 秒），默认重跑全部跳过（23 秒）；包含原卡顿照片的 12 张全部完成（764 秒）。取消触发的原生调用隔离与 88 秒迟到返回后不重启再运行得到实测。213 项 Lua 测试、207 项 TypeScript 测试及独立 MCP 包检查通过。详见[验证记录](../VALIDATION.md)。新增恢复收尾和用户界面确认仍待完成，本文件为待发布草稿。

限制：插件无法强制终止 Lightroom 内部不返回的调用，也不能仅凭“无法显示”提示认定 RAW 文件损坏。五张实测没有复现原生显示故障；模拟故障测试不等于复现了 Lightroom 的原生显示故障。

下载：[插件包](https://github.com/Makashibata02/lightroom-ai-batch/releases/download/v1.0.1/lightroom-ai-batch-plugin-v1.0.1.zip)、[Windows MCP 包](https://github.com/Makashibata02/lightroom-ai-batch/releases/download/v1.0.1/lightroom-ai-batch-mcp-windows-x64-v1.0.1.zip)、[SHA256SUMS](https://github.com/Makashibata02/lightroom-ai-batch/releases/download/v1.0.1/SHA256SUMS)。链接在本版本正式发布后可用。

升级前退出 Lightroom，备份旧配置，将自定义值和 Pop UUID 合并到新版；任务记录保留。不需要删除照片、Catalog、蒙版或集合。

## English

A stability patch with no additional photo-processing stage.

- Definite SDK errors fail promptly; non-editable photos receive a reason, and later photos continue after native work safely ends.
- Denoise, presets and AI masks share a serial gate; actual call return is required, not just visible state.
- Timeout/cancellation drains native work. A call that remains active blocks new submissions with an explicit recovery message instead of silently queueing more jobs.
- Worker cleanup and operation identity checks prevent stale worker flags and late-call interference.
- Menu status/cancel prefer the active job. Repeated menu starts show the existing job. MCP start returns actual QUEUED/RUNNING state.
- Status adds current photo, queue position, heartbeat, SDK return information and recovery requirements; both UI translations are updated.
- Internal plug-in identity, settings and processed records remain compatible. Idempotency `pipelineVersion` stays 1.0.0, so upgrading does not rerun every photo.
- Default reruns finish interrupted empty-mask cleanup without reapplying completed presets. Forced reruns clear the processed flag first and restore it only after successful final checks.

Local acceptance: five test RAWs completed in 508 seconds and their default rerun skipped all five in 23 seconds; a 12-photo test including the previously stalled photo completed in 764 seconds. Cancellation-triggered native-call isolation and new work after an 88-second late return were verified without restarting Lightroom. All 213 Lua tests, 207 TypeScript tests and independent MCP package checks passed. See the [validation record](../VALIDATION.en.md). The new recovery cleanup and human UI acceptance remain pending; these notes are a publication draft.

Limit: the plug-in cannot force-kill a Lightroom native call that never returns, or infer RAW corruption from a display warning. The five-photo test did not reproduce the native display failure; simulated faults do not reproduce Lightroom's native display/GPU failure.

Links become available after this release is published.

Quit Lightroom before upgrading, back up settings and merge custom values/Pop UUID into the new configuration. Job history is retained; no photos, catalog, masks or collections need to be deleted.
